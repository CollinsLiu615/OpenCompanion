# OpenCompanion 手机端 Agent 运行时 · 设计计划

> **状态：规划中，尚未实现。** 当前代码是单次问答式对话，不支持工具调用。
> 这份文档记录设计思路与分阶段方案，供后续开发参考。

## 一、先想清楚：手机上能做哪些工具

Agent 的核心是"能做事"。桌面 Agent（Claude Code / Cursor）的工具都围绕
**文件系统 + 终端**，而手机上这两样要么不存在、要么不该给 AI。

所以不能照抄。手机上的工具必须是**手机上真能做的事**：

| 工具 | 能力 | 权限 | 风险 |
| :--- | :--- | :--- | :--- |
| `web_search` | 联网搜索 | 网络 | 低 |
| `fetch_url` | 读网页正文 | 网络 | 中（防 SSRF） |
| `remember` | 记住一条事实 | 本地存储 | 低 |
| `recall` | 检索记忆 | 本地存储 | 低 |
| `set_reminder` | 设提醒 | 闹钟 | 低 |
| `get_time` | 当前时间 | 无 | 无 |
| `device_info` | 电量/网络 | 系统 API | 低 |
| `send_notification` | 主动发通知 | 通知权限 | 低 |

**明确不做**：读通讯录、读短信、读相册（除头像）、定位、执行任意代码。
理由：这些是"能做事"和"能作恶"的分界线。

## 二、架构：从「问答」到「循环」

### 现在
```
用户消息 → chat_completion → 回复
```

### 目标
```
用户消息
   ↓
┌─────────────────────────────────┐
│  Agent Loop（最多 N 轮）         │
│   1. 发给模型（带工具定义）       │
│   2. 模型要么回复、要么调工具      │
│   3. 是工具 → 执行 → 结果回灌     │
│   4. 回到 1                      │
│   直到：模型给出最终回复           │
└─────────────────────────────────┘
   ↓
最终回复
```

### 关键约束（这几条决定能不能用）

1. **轮数上限**：默认 8 轮，防死循环烧钱
2. **可中断**：用户能随时点"停"
3. **流式输出**：等十几秒没反应会以为卡死
4. **每步可见**：让用户看到"正在搜索…""找到了 3 条"
5. **失败不崩**：工具报错要回灌给模型，让它自己调整

## 三、分阶段

### 阶段 1：能跑起来（最小可用）
- 工具调用协议打通（后端 `chat_with_tools`）
- 3 个只读工具：`get_time` / `web_search` / `remember`
- 单轮工具调用（调一次，拿到结果再回复）
- 不做循环，先验证协议

**验收**：问"现在几点"，AI 调 `get_time` 后正确回答。

### 阶段 2：自主循环
- 多轮循环（最多 8 轮）
- 流式输出 + 中断
- 过程可见（显示正在调什么工具）

**验收**：问"帮我查一下今天上海天气并记住"，AI 依次调
`web_search` → `remember` → 回复，全程有过程提示。

### 阶段 3：手机特色工具
- `set_reminder`（复用现有闹钟）
- `recall`（记忆检索）
- `device_info`

**验收**：AI 能主动设提醒。

### 阶段 4：打磨
- 工具权限开关（用户可禁用某类工具）
- 调用记录可查
- 成本估算（每次对话显示 token 用量）

## 四、必须提前想清楚的三件事

### 1. 钱
多轮工具调用 = 多次 API 请求。一次复杂任务可能 5~8 次。
**必须**：轮数上限 + 用量显示 + 预估费用。
否则用户可能一觉醒来发现欠费。

### 2. 安全
- `fetch_url` 要防 SSRF（禁止访问内网地址）
- 工具参数要严格校验
- 危险操作（如删除记忆）需二次确认
- 模型不能直接读文件

### 3. 体验
手机屏幕上，"思考过程"不能像 Codex 那样刷屏。
建议：折叠式过程提示，最终只保留结果。

## 五、工作量估计

| 阶段 | 内容 | 难度 |
| :--- | :--- | :--- |
| 1 | 协议打通 + 3 个工具 | 中 |
| 2 | 循环 + 流式 + 中断 | 高 |
| 3 | 手机原生工具桥接 | 中高 |
| 4 | 权限与用量 | 中 |

**最大风险在阶段 2 的流式**：安卓 WebView 里 SSE 流式传输有兼容问题，
需要用 `fetch` + `ReadableStream`，旧版 WebView 可能不支持，
要准备降级方案（轮询）。
